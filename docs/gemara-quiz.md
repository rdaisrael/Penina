# Gemara 6 — Quiz WL #2

Student page: `/Penina-Quizzes/gemara-6-wl-2/`. Teacher tools: `/Penina-Quizzes/gemara-6-wl-2/teacher.html`.

All 14 questions and the Talmud image are hosted by Penina. No student request to BookWidgets or a third-party font service is required. The extra-credit annotation boxes are replaced with A/B markers and separately labelled written answers. The original 12 regular points and 4 possible extra-credit points are retained. The original configured timer is intentionally 1,000 minutes (16 hours 40 minutes). Students start with their name and school email, then see one question per page with Previous/Next and a final review page. The deadline is stored on the server and restored across devices; refreshing or reopening cannot reset it. At expiry, the browser locks and submits saved answers, including unanswered questions. If offline or closed, submission is retried when the page is reopened; answers remain saved locally.

Assign the student link using the teacher page's Share to Google Classroom button, or paste the link into an assignment. Students submit in Penina and then turn in the assignment in Classroom. Downloading answers is disabled, matching the original quiz. Link sharing does not transfer grades. The signed-in BookWidgets teacher editor provided the original checked answer key. Ten multiple-choice questions are scored on the server. Questions 3 and 6 (1 point each), and extra-credit questions 13 and 14 (2 points each), require teacher correction. Teacher tools save scores in half-point increments, allow partial review, save feedback, and export scores plus answers in CSV. A final score appears only after all four manually marked questions have scores, including zero where appropriate. The score denominator is 12 regular points; the numerator includes up to 4 extra-credit points. Enter the final grade manually in Classroom until a separate Google connection is configured. The key stays in server-only `lib/quiz-grading.js` until submission: only the accepted submission response provides correct/incorrect feedback and the correct multiple-choice answers. No total score is displayed to students, matching the original configuration. Written-answer keys were blank in the original, so those show awaiting teacher correction.

Reports use `CARD_PUBLISH_KEY_SIXTH`, the existing Sixth Grade publishing password. Storage uses the existing `BLOB_READ_WRITE_TOKEN`. Each immutable submission has a random receipt ID. Student names, email addresses, and answers are encrypted with AES-256-GCM before being written to the public Blob store. The encryption key uses `QUIZ_STORAGE_SECRET`, falling back to `VOCABULARY_PAGE_SECRET`, then the Blob token. Preserve this key across token rotations; before rotating a fallback token, set `QUIZ_STORAGE_SECRET` to its old value. Raw Blob URLs and encryption keys are not exposed by this API.

The assessment handler shares `/api/game-scores?game=assessment` to avoid adding a serverless function. Reports require POST with the teacher password; no student records are available through GET. Submissions validate the question schema and choices on the server. Retries with the same receipt ID return acceptance without overwriting the earlier submission. Identity is student-entered, not authenticated through Google; this workaround does not verify roster membership.

Drafts and completed receipts persist on the student's browser. The completed receipt page has a new-student button to clear the local draft on shared devices. Starting uses an atomic, encrypted, email-keyed attempt record. The same email, normalized for case, retains one receipt and deadline; an accepted submission cannot be replaced. Earlier submissions also prevent another attempt. This restriction relies on entered email rather than verified Google identity. Disabled original tools remain disabled: text highlighting/speech, scratchpad, calculator, Safe Exam Browser, and copy/paste restrictions. Browser spell check is enabled. Fixed question order, points, numbering, autosave, and no immediate per-question answer checking are retained.

Verification: `node --test tests/quiz-submissions.test.js tests/game-scores.test.js`. Check the student and teacher pages on desktop and mobile. Before assigning, verify a real submission is accepted in the deployed storage and appears in the protected report. The school must allow Penina itself; local testing cannot confirm the school's filter rules.

Teacher corrections are append-only encrypted records under `quiz-corrections/gemara-6-wl-2/<receipt>/`. The report uses the most recent saved correction for each receipt. Existing submissions are graded when read, so earlier student work automatically gains multiple-choice scores without being resubmitted. Correction endpoints authenticate the teacher before reading student data or writing grades.

The hosting routes return 404 for the grading module and its answer-key tests, while retaining normal static pages and API routing. The repository itself is public; this is classroom quiz grading, not a secure exam system.
