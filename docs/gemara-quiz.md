# Gemara 6 — Quiz WL #2

## Google sign-in and class access

The current implementation requires Google authentication and a class-specific assignment link. The teacher opens Teacher tools from Penina’s home page, enters the existing Sixth Grade publishing password to connect a Google teacher account, chooses an active class they teach, and creates a 12-point Classroom draft through the API. The teacher opens Classroom to review and publish that draft. Existing drafts are reused; the class link is attached to the assignment. Existing generic links must be replaced in Classroom.

Students use their Google accounts. Names and emails come from a server-verified Google ID token rather than form fields. The stable Google subject identifier is used to check enrollment and bind attempts to both the account and selected class. Every questions request, image request, quiz start and submission checks current Classroom enrollment using the connected teacher’s refresh token. An unavailable roster check, an inactive course, a teacher removed from the class, or an unenrolled student denies access. Students do not grant roster permissions. Teacher reports and correction saving continue to use the existing publishing password. Sending grades also requires a signed-in Google teacher session belonging to the account that created the class assignment.

OAuth authorization uses a short-lived encrypted state cookie, PKCE and a nonce; Google’s official authentication library verifies the ID token signature, issuer, expiry and audience. Session cookies are encrypted, Secure, HttpOnly, SameSite=Lax and expire after 24 hours. POST account and student actions require the canonical Penina Origin. Refresh tokens are encrypted before Blob storage and never sent to browsers. Class links are bound server-side to a teacher, course and quiz; URL changes cannot grant enrollment. Old unauthenticated attempt tokens are rejected.

See [Google Classroom setup](google-classroom-setup.md) for the required Google Cloud client and environment values. Without that setup, sign-in is unavailable and student access fails closed; there is no manual-name fallback. If deployed before configuration is complete, teacher tools show a setup message and new student quiz access remains unavailable until the connection is activated. The owner requested deployment of the completed code on October 12, 2026; activation and a real student test remain separate checks.

Direct public routes to questions.json and talmud-page.png return 404. Authorized responses come through the shared assessment/account API. The repository and previously distributed quiz content have been public, so this access restriction does not retract copies students may already possess. Vercel file tracing must include the local question JSON and image read by the API.

## Grading and test settings

All 14 questions and the Talmud image are hosted by Penina. No student request to BookWidgets is required. The original 12 regular points and 4 possible extra-credit points are retained. Ten multiple-choice answers are graded on the server. Questions 3 and 6 (1 point each) and 13 and 14 (2 extra points each) require teacher correction. Teachers save half-point scores and feedback and can export CSV. Scores stay pending until all manual questions are marked. After all four manual questions have scores, “Save and send grade to Classroom” saves the correction and sends the server-calculated total to both draftGrade and assignedGrade for that student on the stored assignment. Extra credit can exceed the assignment maximum of 12. A published, Penina-created assignment with an unchanged 12-point maximum is required. Turned-in work is then returned. Students mark the assignment done in Classroom; unsubmitted work receives the grade but is not falsely reported as returned. A failed grade send leaves corrections saved and shows a retry message. A failed return is reported separately from a successful grade update. Teacher practice and legacy email-only records cannot send grades.

The original 1,000-minute timer resumes across reloads and cannot be reset. One question appears per page in the original order, followed by review. At expiry the browser locks and submits saved answers, including blanks. If closed or offline, the work is submitted on reopening or retry. Correct-answer feedback appears only after an accepted submission, without a total student score. Downloads are disabled. Spell check is enabled; text-to-speech, scratchpad, calculator and Safe Exam Browser are not enabled.

Drafts and receipts are stored locally under the verified Google subject and class ID. They are shown only after authentication and enrollment checks succeed. One immutable submission is allowed for each Google account/class combination. Existing teacher reports remain readable; prior email-only submissions are not claimed by a newly authenticated account.

## Storage and verification

The assessment and account handlers share `/api/game-scores` under `game=assessment` and `game=quiz-account` to avoid adding a serverless function. Storage uses the existing Blob token and AES-256-GCM encryption. The encryption secret is `QUIZ_STORAGE_SECRET`, falling back to `VOCABULARY_PAGE_SECRET`, then `BLOB_READ_WRITE_TOKEN`. Preserve the same secret if rotating the Blob token. Correction records are append-only and the latest correction is used in reports. Reports require POST with the Sixth Grade publishing password.

Run `node --test tests/quiz-account.test.js tests/quiz-submissions.test.js tests/game-scores.test.js`. Tests cover unauthorized access, current roster checks, identity/class binding, unavailable Google APIs, inactive classes, removed teachers, OAuth state/PKCE/nonce/audience handling, cookie tampering and expiry, encrypted records, grading and correction persistence. Actual Google consent, Google school-admin approval, and deployed API behavior require the real OAuth client; mocked tests cannot establish those.

Classroom-verified teachers of the assigned class can take unlimited practice attempts through the class quiz link. Each new practice attempt has its own timer; the receipt offers “Take the quiz again.” Teacher practice records are encrypted and stored separately from student reports. Students retain one immutable attempt per Google account and class. Teacher status is checked with Classroom on access and submission, never granted from an email address or a client flag.

## Assignment creation recovery

A deterministic class ID and encrypted atomic creation claim prevent duplicate creation on concurrent requests. Retries search the teacher’s Penina-created drafts and published assignments for the exact class link before creating anything. Explicit Google rejections release the claim. Ambiguous failures retain it to avoid duplicate assignments; if no matching draft exists after recovery, the site owner must investigate before removing only that class’s creation claim.
